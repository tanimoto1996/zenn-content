## はじめに：解き方を先に固める

前回の記事では、DOP-C02に880点で合格した勉強法を紹介しました。
ボス図鑑と反射ドリル、「3スロット法」です。

前回の末尾では「次回は①SDLC自動化区から」と書きました。
でも、順番を入れ替えます。
地方ごとのボスを深掘りする前に、解き方そのものを先に固めたほうが、どの地方の記事も読みやすくなるはずや、という判断です。

ここから先は、その3スロット法の完全版です。
手順の全部。判断の優先順位。反射なし問題を切る「デフォルト札」。そして実演2パターン。
私のNotionの原典（5分見返しシート）から、そのまま持ってきました。

:::message
この記事に出てくる問題パターンは、すべて私が学習用に自分の言葉で再構成したものです。本番試験の問題文や選択肢そのものは掲載していません。
:::

## なぜ「全部正解に見える」のか

DOPの問題で一番しんどいのは、知識が足りないことではありません。
選択肢がほぼ全部「動く」ことです。

サービス名と機能を覚えて問題文を読むと、「これも動く、あれも動く」と全部正解に見えます。
最後は勘で選ぶことになります。
これが、普通の読み方で負ける理由やと私は考えています。
私の結論は前回と同じです。

> **DOPは「正解を探す」試験ではなく、「制約に違反する選択肢を消す」試験**。

だから、読む順番を変えます。
ここが肝やと思ってます。
選択肢を見る前に、問題文から「消すための条件」を先に確定させる。
それが3スロット法です。

## 手順：30秒の読解プロトコル

手順は3つだけです。
頭の中だけで回すので、メモは要りません。

### 1. 最終文へジャンプ（5秒）― 基準スロットを確定する

問題文の最後にある基準を先に確定します。
「最も効率的な方法は」「最小の運用負荷で」「最もシンプルな方法は」といった一文です。
これが基準スロットです。

「動くけど過剰」な選択肢は、この時点で、もう負けが決まっています。
基準が「最小コスト」なのに部品の多い構成は、どれだけ正しそうに見えても残りません。

### 2. 本文を高速走査し、制約層だけ精読（10秒）― スロットを最大3つ埋める

スロットに入れる制約は、3種類だけです。

| 種類 | 例 |
| --- | --- |
| **数字** | 時間、件数、サイズ、回数 |
| **否定／禁止** | 「〜してはいけない」「〜は不要」「新規不可」 |
| **順序** | 「〜の後に」「〜してから」「〜の前に」 |

最大3つまで。
4つ目が出てきたら、基準スロットに一番近いものを残して、あとは捨てます。
スロットが増えすぎると消去のキレが落ちます。
ここは欲張ったらあきません。

### 3. 選択肢は違反スキャン（15秒）― 正しさは判定しない

選択肢の正しさは判定しません。
3つのスロットと衝突するかだけを見ます。
違反を消していき、残った1つが答えです。

最後の2択で迷ったら、ここで初めて「部品が少なく、最もマネージド」なほうで決めます。
マネージド度はタイブレーカーであって、フィルタではありません。
制約は、どんなヒューリスティックよりも常に強いです。
この優先順位は、ほんまに崩したらあきません。

## 問題文の3層の読み分け

本文を高速走査するとき、全部を同じ速度で読んだらあきません。問題文は3層に分けて読みます。

- **物語層**（業種・経緯・背景）：ノイズ。0.5秒／行で流す
- **事実層**（現状の構成。CodeCommit・ALB・ASGなど）：名詞だけ拾う。単独では消去力はない
- **制約層**（数字・否定形・比較級・「〜する必要がある」）：ここだけ精読して、スロットに格納する

事実層のポイントは、「制約層と組み合わさって初めて消去力を持つ」ことです。

たとえば「ASGが既にある」という事実だけでは、何も消せません。
でも「新リソース禁止」という制約と組み合わさると、新しい環境を作るデプロイ方式がまとめて消えます。
後で実演します。

## 判定の優先順位：上が絶対

消去するときの優先順位は、決まっています。
上が絶対で、下に行くほど弱くなります。

| 優先 | 消す理由 |
| --- | --- |
| 1 | **制約層への違反 → 即消去**（数字・禁止・順序） |
| 2 | **実在しない機能 → 即消去** |
| 3 | **事実層との矛盾 → 消去** |
| 4 | **残り2択**（最も部品数が少なく・最もマネージドで決める） |

2番目の「実在しない機能」はDOP特有の罠です。
ここ、ほんまに引っかかりやすいところです。
尤もらしい機能名に飛びついてはいけません。

私のノートでは、次の名前を「実在しないもの」として整理しています。

- Extended Retention
- AutoScalingLaunchTemplateUpdate
- Lambdaのキャッシュクリア

マネージド志向が強いほど、この罠にほんまに弱くなります。
「マネージドなら何でもあるはず」という思い込みが、存在しない機能を「あるはずだ」と錯覚させるからです。

## デフォルト札：反射なし問題はこれで切る

引き金が思い浮かばない問題は、「デフォルト札」で切ります。
反射ドリルが刺さらない問題用の札です。
5枚だけ覚えておきます。

| デフォルト札 | 中身 |
| --- | --- |
| 前提＋動詞で決める | 制約＋要件の動詞から決める。サービス名で決めない |
| 迷ったらシンプルに | 最もシンプルで、最小運用負荷の選択肢 |
| バンドルは部品ごとに○× | 部品ごとに判定し、1個でも×なら全体を捨てる |
| 「新規アカウントも自動で」 | OU単位／auto-deploy／CfCT。手動作業入りは全部× |
| 明示Denyは最強 | SCPは権限を与えない |

:::message alert
「明示Denyは最強」の札には続きがあります。SCPは管理アカウント自体にも効きません。
:::

3枚目の「バンドルは部品ごとに○×」は、特に効くんです。
3つ入っているうち2つが正しくても、1つが制約違反なら選択肢ごと捨てます。
部分点のない試験では、「ほぼ正しい」は「間違い」と同じです。

## 実演1：SCPのボスを3スロットで切る

前回のボス1で実演します。パターンの要約は、前回と同じ自分の言葉での再構成です。

**パターン**：運用アカウントから、各メンバーアカウントへ管理者アクセスを渡したい。選択肢の1つに「SCPでフルアクセスを許可する」がある。

| ステップ | 内容 |
| --- | --- |
| **最終文へジャンプ** | 基準は「管理者アクセスを渡す」＝「権限の付与」 |
| **制約層だけ精読** | スロットに入る制約は1つで十分です。**①「付与」が目的であること** |
| **3層の読み分け** | 事実層の名詞は拾う。物語層は流す |
| **違反スキャン** | 「SCPで許可」は付与できず制約①に違反 → **即×** |
| **残る形** | メンバー側にロール＋信頼ポリシーでAssumeRole |

サービス名の知識だけで戦うと、「SCP＝Organizationsの強いやつ＝権限をどうにかできるはず」という連想で負けます。
制約で切ると、連想が入り込まなくなるんです。

## 実演2：既存ASG × 新リソース禁止

2つ目は、私のノートにある「事実層×制約層」の組み合わせパターンです。こちらも自分の言葉で再構成したパターンです。

**パターン**：Auto Scalingグループ（ASG）で動いているサービスをデプロイし直したい。新しいリソースの追加はできない。最小の変更でデプロイしたい。

| ステップ | 内容 |
| --- | --- |
| **最終文へジャンプ** | 基準は「最小の変更でデプロイする」こと |
| **制約層だけ精読** | スロットは2つ。**①新リソース禁止 ②既存ASGを使い続ける** |
| **違反スキャン** | Blue/GreenもImmutableも新環境を作るので**即×** |
| **残る形** | 既存ASG内で入れ替えるローリングだけが残る |

補足します。
Blue/GreenもImmutableも、新しい環境を作って切り替える方式です。
だから「新リソース禁止」に触れて、まとめて消えます。

「ASGが既にある」という事実だけでは、どのデプロイ方式も消せません。
「新リソース禁止」の制約と組み合わさった瞬間に、新環境を作る方式がまとめて消えます。
これが、事実層と制約層の組み合わせの威力やと思います。

## 反射でよい変換：数字は即答に変える

制約層の数字は、覚えた数値と結びつけて即答に変えます。私のノートで鍛えている変換はこのあたりです。

| 引き金（問題文のワード） | 即答 |
| --- | --- |
| 処理に2時間かかる | Lambdaは最大15分。2時間の処理には使えない |
| 5000件を同時に処理する | Lambdaの同時実行は既定1,000。5,000同時は超える |
| 監査・継続監視・コンプライアンス | Config |
| 改ざんの検証 | CloudTrailの整合性検証 |
| プロビジョニング不要 | S3 |
| 256KB超のペイロード | 本体はS3に置いて参照渡し |
| PIIの検出 | Macie |

:::message
「プロビジョニング不要」の対比です。OpenSearchやRedshiftはプロビジョニングが必要になります。
:::

数字の変換は、暗記の量をほんまに減らしてくれるんです。
「2時間」の数字を見た瞬間に「Lambdaは15分まで」が浮かべば、選択肢を読む前に1つ消せます。

なお、Lambdaの同時実行数の既定1,000は、引き上げ申請ができる枠です。
「超えたら即×」ではなく「既定のままでは足りない」という読み方が正確です。

## 練習方法：5分見返しシートの回し方

この3スロット法は、読んで覚えるものではありません。
回して体に付けるものです。
私の練習方法は、前回の記事で紹介した5分見返しシートと同じです。

| # | やること |
| --- | --- |
| 1 | 引き金（左列）だけ見て、右列の即答を口で言う |
| 2 | 詰まった行だけ、リンク先のボスページへ戻る |
| 3 | 読み返さず、思い出す。思い出せなかった行だけ繰り返す |

毎日5分で十分です。
ほんまに、それだけで変わります。
30秒プロトコルは問題を解くたびに「最終文→制約3つ→違反スキャン」の順を意識するだけです。
回数が増えるほど速くなります。
