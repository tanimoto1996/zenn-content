## なぜ普通の暗記で詰んだか

DOPはとにかく範囲が広い。

CI/CD、IaC、セキュリティ統制、監視、回復力、障害対応。

6つのドメインに、数十のサービスと、その「細かい設定」までが乗ってきます。

最初は王道に、サービス名と機能を丸暗記しようとしました。

でもDOPの問題は「CodeDeployの機能はどれか」みたいな聞き方をしてくれません。

出てくるのは長い状況文です。

「この状況で、最も運用負荷が低く、要件を全部満たすのはどれか」という形です。

つまり必要なのは、知識の「点」ではありませんでした。

必要なのは**判断のパターン**です。

| 判断すること | 中身 |
| --- | --- |
| 引き金 | 状況文のどの言葉がトリガーワードか |
| 選定 | どのサービスを、どの設定で使うか |
| 消去 | なぜ他の選択肢が「動くけど負け」なのか |

暗記すべきはサービス名ではなく、この判断のほうだったんです。

## 世界観バイブル：DOPをRPGの世界に置き換える

そこで作ったのが「世界観バイブル」です。

置き換えのルールはシンプルです。

| ルール | 中身 |
| --- | --- |
| サービスは「役割」で捉える | 「機能」ではなく、担当の役割から覚える |
| 設定・数値こそ暗記の本体 | 同じサービスでも、どの設定が勝敗を分けるかで整理する |
| 問題の状況 ＝ ボス | ボスには必ず弱点＝トリガーワードがある |

そして試験の6ドメインを、そのまま世界の6地方として地図にしました。

割合は公式の試験ガイドにある配分です。

| 地方（ドメイン） | 配分 |
| --- | --- |
| ① SDLC自動化区 | 22% |
| ② IaC・設定管理区 | 17% |
| ③ セキュリティ・統制区 | 17% |
| ④ 回復力・自己治癒区 | 15% |
| ⑤ 監視・観測区 | 15% |
| ⑥ 障害対応・事件区 | 14% |

この置き換えの効き目は、「設定の暗記」が「勝敗条件の暗記」に変わることです。

地味な細かい仕様も、倒すボスの条件だと分かると頭に残ります。

## 実例：ボス図鑑から3体だけ紹介します

### ボス1：「SCPで許可」という幻術

「運用アカウントから各メンバーアカウントへ管理者アクセスを渡したい」というタイプの問題で、私は「SCPでフルアクセスを許可する」という選択肢を掴んで被弾しました。

討伐メモはこうです。

| 項目 | 中身 |
| --- | --- |
| 法則 | **SCPは権限を1ミリも付与しない** |
| 正解の形 | メンバー側にロール＋信頼ポリシーでAssumeRole |
| 教訓 | 「SCP＋許可／付与」を見たら即✕ |

③セキュリティ・統制区のボスの多くは、この「SCPは与えない」という1本の法で切れます。

SCPは「使える上限」を決めるだけ。

許可はしません。

正解の形は、入られる側にIAMロールを用意することです。

メンバーアカウントにIAMロールを作ります。

信頼ポリシーで入る側（運用アカウント）を指定し、AssumeRoleさせます。

反射ドリルにも、そのまま入れています。

「組織で禁止／rootも縛る → SCP。与えない・管理アカウント対象外・明示Deny最強」

:::message alert
SCPは管理アカウント自体には効きません。
これも定番のひっかけポイントです。
:::

### ボス2：AllowTraffic無言死

CodeDeployのデプロイが AllowTraffic の段階で失敗するのに、**ログが何も出ていない**――というタイプの問題です。

討伐メモはこうです。

| 項目 | 中身 |
| --- | --- |
| イベントの種類 | スクリプト式（ログあり）／自動処理（ログなし） |
| 疑う先 | **ALBのヘルスチェック設定**（スクリプトのバグではない） |
| 教訓 | **ログ無し＝スクリプト無し**。犯人はALBのヘルスチェック設定 |

AllowTraffic のような自動イベントは、スクリプト自体がありません。

だからログが出ないのは異常ではなく仕様です。

「ログが出ていない」ことを手がかりに使える。

それがこのボスの学びでした。

①SDLC自動化区と④回復力区にまたがる、個人的に好きなボスです。

### ボス3：Parameter Store と Secrets Manager の境界

似た者同士の2サービスは、「要件のキーワード」で即断します。

私のパターン表では、こう整理しています。

| 要件 | 選ぶもの |
| --- | --- |
| シンプルな設定値 | Parameter Store |
| ローテーション不要な秘密情報 | Parameter Store（SecureString） |
| **DB認証情報の自動ローテーション** | **Secrets Manager** |
| RDS / Redshift / DocumentDB との統合 | Secrets Manager |
| コスト最小化 | Parameter Store（無料枠あり） |
| クロスアカウント共有 | Secrets Manager（リソースポリシー） |

合言葉は「**自動ローテーションが出たら Secrets Manager**」。

逆に「保管だけ」のものまで寄せると、コストと運用で負けます。

## 解き方の核心：3スロット法

世界観が「覚え方」だとしたら、3スロット法は「解き方」です。

私の勉強の結論を1文で言うと、こうなります。

> **DOPは「正解を探す」試験ではなく、「制約に違反する選択肢を消す」試験**。

選択肢はほぼ全部「動く」ものばかりです。

普通に読むと全部正解に見えます。

だから読む順番を変えます。

### 手順

| # | 時間 | やること |
| --- | --- | --- |
| 1 | 5秒 | **最終文へジャンプ** |
| 2 | 10秒 | **本文を高速走査し、制約層だけ精読** |
| 3 | 15秒 | **選択肢は違反スキャン** |

:::details 各ステップのポイント
- **最終文へジャンプ**：最後の基準（最小の運用負荷など）を先に確定する
- **制約層だけ精読**：制約（数字・否定／禁止・順序）を最大3つ拾う
- **違反スキャン**：スロットと衝突するかだけ見て、違反を消す
:::

判定の優先順位も決めています。

| 優先 | 消す理由 |
| --- | --- |
| 1 | 制約層への違反 |
| 2 | 実在しない機能 |
| 3 | 事実（現在の構成）との矛盾 |

確定した基準が「基準スロット」です。

「動くけど過剰」な選択肢は、この時点で負けが決まります。

本文で拾う制約は、数字・否定／禁止・順序の3種類だけ。

業種や経緯などの物語はノイズとして流します。

選択肢は正しさを判定しません。

違反したものを消すと、残った1つが答えです。

マネージド度は、最後のタイブレーカーとしてだけ使います。

最後の2択で迷ったときに「部品が少なく、最もマネージド」なほうで決めます。

### 実演：ボス1を3スロットで切る

さっきのボス1（他アカウントへ管理者アクセスを渡したいパターン）で実演します。

私が練習用に作ったパターンの要約です。

| ステップ | 内容 |
| --- | --- |
| 最終文の基準 | 必要なのは「権限の付与」 |
| スロット | 制約は1つで十分。**①「付与」が目的であること** |
| 違反スキャン | 「SCPで許可」は付与できず制約①に違反 → **即✕** |
| 結果 | 残るのはロール＋信頼ポリシー＋AssumeRoleの形 |

サービス名の知識だけで戦うと、「SCP＝Organizationsの強いやつ＝権限をどうにかできるはず」という連想で負けます。

制約で切ると連想が入り込む余地はありません。

## 反射ドリル：引き金→即答のサンプル

仕上げに、試験直前の5分で見返していた「反射ドリル」から、数行だけ公開します。

左の「引き金」だけ見て、右を即答できるか試してみてください。

| 引き金（問題文のワード） | 即答 |
| --- | --- |
| 組織全体で禁止／rootも縛る | SCP。与えない・管理アカウントに効かない・明示Deny最強 |
| DB認証情報の自動ローテーション | Secrets Manager |
| ステージングで機能テスト（2時間超）→成功したら本番へ | Step Functions＋コールバックでCodePipelineへ返す |
| 組織全体にWAFを強制適用 | Firewall Manager 一択（Configは検知まで、強制はできない） |
| インストール済みアプリの監査／棚卸し | SSM Inventory ＋ Configルール（禁止判定） |
| 設定を継続的に評価・監査・監視 | Configルール（設定）＋ CloudTrail（操作）の監査コンビ |
| ECSデプロイ＋最小オーバーヘッドでテスト追加 | 標準のローリング（`imagedefinitions.json`） |
| 256KB超のペイロード | 本体は S3 に置いて参照渡し |

:::details ドリル表の補足
- パイプライン自体は長時間待てないので、テストは外で回して結果だけ返します
- appspec＋CodeDeployの構成は重いので、最小オーバーヘッドとは相性が悪いです
- 監査／棚卸しは、SSM Inventoryで収集し、Configルールで禁止判定します
:::

ドリル表とボス図鑑は、全地方分があります。

まずはこの8行で感覚を掴めれば十分です。
