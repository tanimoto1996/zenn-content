## はじめに：880点でした

2026年11月7日、AWS Certified DevOps Engineer - Professional（DOP-C02）を受験し、**880点で合格**しました。合格ラインは750点なので、+130点です。

私は2021年からWebシステム開発の現場で働く、バックエンド×クラウドインフラのエンジニアです（Laravel / Vue / AWS CDK が主戦場）。実務でAWSを触っている側の人間ですが、それでもDOPの勉強は一筋縄ではいきませんでした。

この記事では、私が合格のために作った少し変わった勉強法――**DOPをRPGとして攻略する「世界観バイブル」と、問題の解き方そのものである「3スロット法」**――を公開します。どちらも、暗記に詰んだ末に生まれた仕組みです。

:::message
この記事に出てくる「ボス」や問題パターンは、すべて私が学習用に自分の言葉で再構成したものです。本番試験の問題文や選択肢そのものは掲載していません。
:::

## なぜ普通の暗記で詰んだか

DOPはとにかく範囲が広い。CI/CD、IaC、セキュリティ統制、監視、回復力、障害対応――6つのドメインに、数十のサービスと、その「細かい設定」までが乗ってきます。

最初は王道に、サービス名と機能を丸暗記しようとしました。でもDOPの問題は「CodeDeployの機能はどれか」みたいな聞き方をしてくれません。出てくるのは長い状況文で、「この状況で、最も運用負荷が低く、要件を全部満たすのはどれか」という形です。

つまり必要なのは知識の「点」ではなく、

- 状況文のどの言葉が引き金か（トリガーワード）
- どのサービスを、どの設定で使うか
- なぜ他の選択肢が「動くけど負け」なのか

という**判断のパターン**でした。暗記すべきはサービス名ではなく、この判断のほうだったんです。

## 世界観バイブル：DOPをRPGの世界に置き換える

そこで作ったのが「世界観バイブル」です。置き換えのルールはシンプルです。

- **サービスは「機能」ではなく「役割」で捉える**（何をする担当なのか、から覚える）
- **細かい設定・数値こそ暗記の本体**（同じサービスでも、どの設定が勝敗を分けるかで整理する）
- **問題の状況 ＝ ボス**（ボスには必ず弱点＝トリガーワードがある）

そして試験の6ドメインを、そのまま世界の6地方として地図にしました。割合は公式の試験ガイドにあるドメイン配分です。

| 地方（ドメイン） | 配分 |
| --- | --- |
| ① SDLC自動化区 | 22% |
| ② IaC・設定管理区 | 17% |
| ③ セキュリティ・統制区 | 17% |
| ④ 回復力・自己治癒区 | 15% |
| ⑤ 監視・観測区 | 15% |
| ⑥ 障害対応・事件区 | 14% |

この置き換えの効き目は、「設定の暗記」が「勝敗条件の暗記」に変わることです。地味で覚えられなかった細かい仕様ほど、どのボスを倒す条件なのかが分かると頭に残るようになりました。

## 実例：ボス図鑑から3体だけ紹介します

### ボス1：「SCPで許可」という幻術

「運用アカウントから各メンバーアカウントへ管理者アクセスを渡したい」というタイプの問題で、私は「SCPでフルアクセスを許可する」という選択肢を掴んで被弾しました。

討伐メモはこうです。

- **SCPは権限を1ミリも付与しない**。SCPは「Denyの上限」を決めるガードレール専用
- 正解の形は、**入られる側（メンバーアカウント）にIAMロールを作り、信頼ポリシーで入る側（運用アカウント）を指定して AssumeRole** させる
- 教訓：「SCP＋許可／付与」という字面を見たら、その選択肢は即✕

③セキュリティ・統制区のボスの多くは、この「SCPは与えない」という1本の法で切れます。反射ドリルにも「組織全体で禁止／rootも縛る → SCP。与えない・管理アカウントに効かない・明示Deny最強」とそのまま入れています（※SCPが管理アカウント自体には効かない、というのも定番のひっかけポイントです）。

### ボス2：AllowTraffic無言死

CodeDeployのデプロイが AllowTraffic の段階で失敗するのに、**ログが何も出ていない**――というタイプの問題です。

討伐メモはこうです。

- CodeDeployのライフサイクルイベントには、フックスクリプトが動くもの（ログが出る）と、自動で処理されるもの（AllowTraffic など、スクリプトが無い＝**ログも出ない**）がある
- つまり「ログ無しの失敗」は、スクリプトのバグではなく **ALBのヘルスチェック設定**を疑うのが定石
- 教訓：**ログ無し＝スクリプト無し**。犯人はALBのヘルスチェック設定

「ログが出ていない」ことを手がかりとして使える、というのがこのボスの学びでした。①SDLC自動化区と④回復力区にまたがる、個人的に好きなボスです。

### ボス3：Parameter Store と Secrets Manager の境界

似た者同士の2サービスは、DOPでは「要件のキーワード」で即断します。私のサービス選択パターン表ではこう整理しています。

| 要件 | 選ぶもの |
| --- | --- |
| シンプルな設定値 | Parameter Store |
| ローテーション不要な秘密情報 | Parameter Store（SecureString） |
| **DB認証情報の自動ローテーション** | **Secrets Manager** |
| RDS / Redshift / DocumentDB との統合 | Secrets Manager |
| コスト最小化 | Parameter Store（無料枠あり） |
| クロスアカウント共有 | Secrets Manager（リソースポリシー） |

合言葉は「**自動ローテーションが出たら Secrets Manager**」。逆に「保管すればいいだけ」のものまで Secrets Manager に寄せると、コストや運用の観点で負ける選択肢になります。

## 解き方の核心：3スロット法

世界観が「覚え方」だとしたら、3スロット法は「解き方」です。私の受験勉強の結論を1文で言うと、こうなります。

> **DOPは「正解を探す」試験ではなく、「制約に違反する選択肢を消す」試験。**

選択肢はほぼ全部「動く」ものばかりなので、普通に読むと全部正解に見えます。だから読む順番を変えます。

### 手順

1. **最終文へジャンプ（5秒）** ―― 問題文の最後にある「最も効率的な方法は」「最小の運用負荷で」などの基準を先に確定する。これが基準スロット。「動くけど過剰」な選択肢は、この時点で負けが決まる
2. **本文を高速走査し、制約層だけ精読（10秒）** ―― 数字・否定／禁止・順序、の3種類の制約を最大3つまで拾ってスロットに入れる。業種や経緯などの物語部分はノイズとして流す
3. **選択肢は違反スキャン（15秒）** ―― 正しさを判定するのではなく、3つのスロットと衝突するかどうかだけを見る。違反した選択肢を消していき、残った1つが答え。最後の2択で迷ったら「部品が少なく、最もマネージド」なほうで決める

判定の優先順位も決めています。制約層への違反 → 実在しない機能 → 事実（現在の構成）との矛盾、の順に消去し、マネージド度は最後のタイブレーカーとしてだけ使います。

### 実演：ボス1を3スロットで切る

さっきのボス1（他アカウントへ管理者アクセスを渡したいパターン）で実演します。あくまで私が練習用に作ったパターンの要約です。

- 最終文の基準：「運用アカウントから、**各メンバーアカウントへ管理者アクセスできるように**したい」＝必要なのは「権限の付与」
- スロットに入る制約は1つで十分：**①「付与」が目的であること**
- 違反スキャン：「SCPでフルアクセスを許可する」→ SCPは付与ができない（上限を決めるだけ）ので、制約①に違反 → **即✕**
- 残るのは「メンバー側にロール＋信頼ポリシー＋AssumeRole」の形。これが討伐完了です

サービス名の知識だけで戦うと「SCP＝Organizationsの強いやつ＝権限をどうにかできるはず」という連想で負けます。制約で切ると、連想が入り込む余地がありません。

## 反射ドリル：引き金→即答のサンプル

仕上げに、試験直前の5分で見返していた「反射ドリル」から、数行だけ公開します。左の「引き金」だけ見て、右を即答できるか試してみてください。

| 引き金（問題文のワード） | 即答 |
| --- | --- |
| 組織全体で禁止／rootも縛る | SCP。与えない・管理アカウントに効かない・明示Deny最強 |
| DB認証情報の自動ローテーション | Secrets Manager |
| ステージングで機能テスト（2時間超）→成功なら本番へ | テストを Step Functions でつなぎ、結果をコールバックで CodePipeline に返す（パイプライン自体は待てない） |
| 組織全体にWAFを強制適用 | Firewall Manager 一択（Configは検知まで、強制はできない） |
| インストール済みアプリの監査／棚卸し | SSM Inventory（収集）＋ Configルール（禁止判定） |
| 設定を継続的に評価・監査・監視 | Configルール（設定）＋ CloudTrail（操作）の監査コンビ |
| ECSデプロイ＋最小オーバーヘッドでテスト追加 | 標準のローリング（imagedefinitions.json）。appspec＋CodeDeployは重い |
| 256KB超のペイロード | 本体は S3 に置いて参照渡し |

全部で地方ごとのドリル表とボス図鑑があるのですが、まずはこの8行で「引き金→即答」の感覚が掴めれば十分だと思います。

## おわりに：これから書くこと

880点は結果ですが、再現性があるのはこの仕組みのほうだと思っています。暗記を「ボスを倒す条件集め」に置き換えること。そして問題は正解探しではなく、制約違反の消去で解くこと。
